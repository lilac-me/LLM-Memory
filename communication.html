Profiling → 实际有效带宽

本地解析 · 分组比较 · 明确确认后回填

先用脚本流式解析 trace.json / trace_view.json 与 kernel_detail(s).csv，再导入生成的 communication_profile.json。原始 profiling 不上传服务器；本页只保留你选择的带宽校准条目。

下载解析脚本
python profiling_parser.py --trace trace_view.json --kernels kernel_details.csv --output-dir comm_audit
# 可选：--model-config config.json 区分 FC2 维度；--device 0 选择设备

大于 64 MiB 的 trace 需要 ijson（python -m pip install ijson）。可用 --start-us / --end-us 指定同一完整 step 窗口；只纳入完整调用，不用截断后的时长反算整条消息带宽。AllGather / ReduceScatter 默认按 API 的 shard count 作假设解释，--fsdp-count unknown 可保留未知；AllToAll 默认用邻近输出 shape 检查 count。

有效 GB/s = Σ逻辑 bytes / Σ集合算子设备时长，含等待；小消息往往受启动/同步等待支配，不能只用吞吐解释。P50/P95 用于观察长尾。校准须核对算子、group、dtype、消息大小、拓扑与训练阶段；只匹配消息大小 ±10% 的计算项。采用实测有效速率的项不再叠加启动延迟。H2D/D2H 没有方向及 DMA bytes 证据时不自动回填。

计算口径

  • AllToAll dispatch 的 N = prod(permute 数据输出 shape) × dtype bytes；combine 的 N = prod(FC2 数据输出 shape) × dtype bytes。缺少实际 shape 时，模型预测为 seq_length × micro_batch_size × num_experts_per_tok × hidden_size（Latent MoE 使用 latent_h），并标为预测；实测 shape 不再乘 top-K / EP / 不均衡系数。
  • 均衡 AllToAll 每 rank 远端发送量 = N × (EP−1)/EP。标准 ring 等价 AllGather / ReduceScatter 发送量 = N × (group−1)/group，AllReduce 再乘 2。group=1 不产生设备间通信。这里没有把接收量再加到分母。
  • 时间 = 所选口径 bytes / (GB/s × 10⁹) + 调用次数 × 启动延迟。前向/反向参数均按 BF16，梯度采用共享的 reduce dtype。一次完整 MoE 前反向是 4 次 AllToAll，完整重放另加 2 次。
  • FSDP 先定义本组负责的一层完整参数 P_layer：AllGather 完整量=P_layer×参数 bytes，本地 shard=P_layer/group，远端量=P_layer×bytes×(group−1)/group；ReduceScatter 用同一 P_layer×梯度 bytes。非路由 group=world_size；专家所属组用 ep_fsdp_size。EP 只决定专家归属：已经是本组单层参数/shape 的数字不再除 EP，EP 分配本身也不是一次 FSDP 通信。默认每个 micro batch 前向后释放完整权重，反向重新 gather。预取改变时序，不增加总字节。
  • 一项同 dtype、同通信组的计算单位视作一次调用；实际 bucket、参数 padding、多 dtype 及分组算法会改变调用数。AG/RS 同类带宽目前共用一个输入，需按真实组拓扑校准。
  • 本页覆盖 FSDP × EP 的 AllToAll、AllGather、ReduceScatter 和可选 AllReduce；未启用的 TP/PP/CP 不自动添加通信。路由索引/权重元数据、跨节点拓扑和融合/去重发送需结合实现追加。

定义参考：NCCL tests 带宽口径 · HCCL sendCount / recvCount 接口 · FSDP 参数 gather 与梯度规约。公式用于比较口径，不代表 Ascend HCCL 采用相同算法。
